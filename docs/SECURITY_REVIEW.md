# 0.1.1 安全检查与优化

日期：2026-11-17。范围包括 MoonBit 解析/匹配实现、vendored 正则编译器、Node 文件/JSON/Worker 边界及发布文件。属于源码审查与针对性回归测试，不是完整安全认证。

| 问题 | 修复 |
| --- | --- |
| 短正则的巨大计数或嵌套重复可在编译时展开大量指令，纯库调用没有 Worker 保护 | AST 编译前计算保守成本并饱和截断，超过 100000 拒绝；空表达式的重复也计算循环成本。核心适配器限制分组深度 64、分支分隔符 256 |
| 外部变量先展开再检查最终长度，可产生不必要的大分配 | 变量数、变量名/值预检查；逐片段检查展开预算 |
| 空批量 JSON 请求无测试却返回成功 | 宿主只接受 1..4096 项批量请求 |
| 终端失败摘录、规则和文件名可携带 ANSI/OSC 或双向文本控制字符 | 文本终端输出转义控制字符；JSON 报告保留数据语义 |
| 诊断摘录在 UTF-16 第 240 单元切断补充平面字符 | 截断点避开代理项中间位置 |
| 导出 evaluate API 未验证超时、请求大小 | API 与 CLI 统一验证超时范围；序列化请求最多 16 MiB，直接传序列化字符串到 Worker，避免再次序列化 |

安全回归：`node scripts/security.mjs` 共 18 项；MoonBit 新增 3 个主库测试及 1 个依赖编译预算测试，覆盖三个后端。原始结果见 `evidence/security.json`。

性能：ASCII 边界分类直接判断；顺序匹配的行列定位复用上次扫描位置。2000 条顺序规则、约 200 KiB 输入，包含 Worker 启动，预热后各测 3 次，旧版/新版中位数 4984/421 ms。此结果仅适用于该场景；无序回退、正则匹配与分配仍可能昂贵。原始记录在 `evidence/optimization.json`。

CI Actions 固定到不可变提交，并设置 job 超时与 contents: read 权限。

剩余边界：纯库 API 仍需调用方限制执行资源；Worker 堆上限并非整个进程 RSS 上限；文件读取超时没有覆盖等待标准输入；不宣称覆盖 Rust regex 全部语义。兼容限制见 COMPATIBILITY.md。
